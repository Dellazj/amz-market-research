## ⭐ 关键数据提取技术
从 `category_report` 的 `category_stats_report` 一次拿到：CR3产品/品牌/卖家三 share、Amazon自营share、#1单品share、高评分share、高评论share、均价/中位价。**无需额外调用**，解析该 dict 即可。

- 新品销量占比：遍历 `top100_products` 的 `online_date`，`年龄=(今天-上线日).days<=90` 累加该批月销量 ÷ Top100总销量。
- 价格带分布：按 price 分桶（<10/10-30/30-50/50-70/70-100/100+）统计款数+销量占比。
- 1688出厂成本：`ali1688_similar_product` 拉100条，解析 `price` 字段得到工厂价区间（如蒸面器 ¥4.5–260，主流热喷款 ¥25–65≈$3.5–9）——用真实价格填充款式-成本表。

## ⭐ 大报告的模块化生成 + 生成后校验（生产实证）
**大报告（5大板块多表格）别写成一个几千行的巨型脚本**——难改难查。可靠做法：
1. **分部件生成**：拆成 `gen_xxx_p1.py`…`p5.py`，每个部件顶层定义 `S1..S5 = sec('一','xxx',src, body)`（字符串变量），各自复用相同的 `src/sec/sub/note` 辅助小函数（每个文件里内联一份即可，简单自洽），各自 `write_file` 存为 `_partN.py`（内容 `Sx = <repr>`）。**先单独运行每个 part 编译验证**（`python3 gen_pN.py`，报错即定位到该部件，不会拖累整份）。
2. **主脚本 importlib 汇总**：`importlib.util.spec_from_file_location` 逐个加载 5 个 part 模块拿到 `S1..S5`，再拼 hero + AI总结 + S1..S5 + foot。CSS 从第一个 part 模块（`m1.CSS`）取，避免重复定义。
3. **生成后必跑 HTML 校验**（不能只看"文件生成了"就部署）：
   - 标签配对：`for tag in tags: 开=re.findall(r'<tag[\s>]',html); 闭=re.findall(r'</tag>',html)`，`<li>` 常凑不齐。
   - 不平衡时**按 `<section class="sec">` 切段**，逐段再数，定位是哪一板块缺闭合——比全文找快得多。
   - 检查 5 大板块 `<span class="no">一..五</span>` 都在、无 Python 代码泄漏（搜 `s1_body`/`def `/`append`）、关键小节标题在（`产品痛点`/`波特五力`/`FABE`/`SWOT`/`蓝海`…）。
   - 修完 unbalance 再重新生成一遍全文。
